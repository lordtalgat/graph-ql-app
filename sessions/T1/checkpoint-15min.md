- **Stuck:** was blocked for roughly 10 of the 15 minutes on `DBSchema.createDatabase` throwing `Table "USERS" not found` on every single invocation — unrelated to this task's edit, but it meant *no* test (mine or any future one) could ever get past database setup. No longer stuck: root-caused and fixed (see Discovered).
- **Discovered:** `DBSchema.databaseSetup` creates and seeds `LINKS` before `USERS`, even though `LinksTable` declares a `foreignKey(..., Users)`. Slick emits that FK as an `ALTER TABLE LINKS ADD CONSTRAINT ...` as part of `Links.schema.create` itself — so it runs immediately, before `Users.schema.create` ever executes, and fails every time. This is a pre-existing defect, invisible until something actually exercises `DBSchema.createDatabase` under test — which nothing in this repo did before today (zero tests existed). Neither plan.md nor tasks.md anticipated it.
- **Rejected:** I considered writing the resolver defensively — `ctx.ctx.currentUser.getOrElse(throw AuthorizationException(...))` — as a second auth check inside `createVote` itself, in case the `Authorized` tag/middleware guarantee ever lapsed. Redirected myself away from it: `AuthMiddleware.beforeField` already guarantees `currentUser.isDefined` before this resolver runs (same contract `createLink` already relies on implicitly), so a second check duplicates that guarantee instead of trusting it — plain `.get` is the correct, minimal implementation, not a shortcut.
